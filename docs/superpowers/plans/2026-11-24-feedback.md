# Feedback Project 1 (Requesters and Feedback) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Issues carry feedback from people outside the workspace (Linear's `CustomerNeed` with a requester attachment, requesters as `ExternalUser`), shown on issues, projects, lists, Insights and a People page.

**Architecture:** Tasks 1–2 build the API (tables, Linear's GraphQL surface, the instance endpoints for requesters and the requester attachment). Tasks 3–5 build the web: the issue and project sections, the list / Insights integration, and the People pages with the smoke check.

**Tech Stack:** Bun, Elysia, Drizzle, graphql-yoga (Linear's SDL, never edited), better-auth instance plugin; Next.js 15, React 19, TanStack Query 5, gql.tada, Recharts; `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-24-feedback-design.md`

## Global Constraints

- Linear's SDL is never edited; `gql.tada check` passes. Incremental migrations.
- One requester per lowercased email; requesters without email allowed.
- Members, admins and owners who may edit an issue may add / edit / move / delete its feedback; guests may not, and see no requester names, emails or quotes (count only).
- Merging requesters: owners and admins only.
- Feedback creates no notification and runs no workflow; `CustomerNeed` webhook events are sent where a webhook subscribes to the `CustomerNeed` resource type.
- While Customers are off, `customerCount` = distinct requesters with feedback on the issue; `customerImportantCount` = distinct requesters with important feedback.
- Commit per task, no trailer. Questions settled the way Linear does.

## Review Focus

1. A guest reading an issue with feedback through GraphQL (`Issue.needs`, `customerNeeds`, `customerNeed(id)`, `Attachment.externalUserCreator`, `IssueHistory`, webhooks they cannot see anyway): no names, emails or quotes; counts only. Test in Task 1.
2. Two requesters created at the same time with the same email (different case): one requester, the second call returns it. Test in Task 2.
3. Merging A into B when both gave feedback on the same issue: one person counted, both quotes kept; A's email becomes free only if B had none (B keeps its own email otherwise). Test in Task 2.
4. Moving feedback to an issue in a team the user cannot edit, or deleting an issue with feedback: refused / feedback deleted with its attachment, counts updated. Test in Task 1.
5. Feedback on an archived issue: still listed on the requester's page with the issue marked archived; not counted in list ordering of active issues. Test in Task 1 / Task 5.
