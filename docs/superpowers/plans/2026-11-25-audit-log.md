# Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An append-only workspace audit log of security-relevant actions, readable by owners and admins in Settings and through Linear's `auditEntries`, with CSV export and owner-chosen retention.

**Architecture:** `apps/api/src/audit/` holds the store (`recordAudit`), the type registry, the request-details context, retention and export. Every action calls `recordAudit` inside its transaction when it has one, else directly with fail-open handling. better-auth hooks in `packages/auth` call into a hook the API registers at startup (the auth package does not import the API).

**Tech Stack:** Bun, Elysia, better-auth, Drizzle/Postgres, graphql-yoga with Linear's SDL, the worker, Next.js 15, gql.tada.

**Spec:** `docs/superpowers/specs/2026-11-25-audit-log-design.md`

## Global Constraints

- Linear's SDL is never edited; `gql.tada check` passes. Incremental migrations. Follow the AGENTS.md files and DESIGN.md.
- Entries are append-only: no code path updates or deletes an entry except the retention clean-up.
- No secret (key, token, password, magic link, OAuth secret) and no issue content in any entry.
- Outside a transaction a failed write lets the action proceed, logs `[audit] entry not written`, and the next written entry carries `metadata.missedEntries: n`.
- `loginFailed`: one entry per attempted address + IP per 10 minutes, `metadata.attempts` counting.
- IP: connection address, or `X-Forwarded-For` / `X-Real-IP` only when `TRUST_PROXY=true`; country from `CF-IPCountry` only when `TRUST_PROXY=true`, else null.
- Retention: `30d` (default), `90d`, `1y`, `2y`, `3y`, `forever`; owners only; the worker deletes older entries daily.
- Readers: owners and admins; an OAuth token needs the `admin` scope; others FORBIDDEN.
- Commits: one per task, no trailer or metadata.

## Review Focus

1. A role change that fails validation after the audit insert leaves no entry (same transaction). Test in Task 3.
2. Forcing the audit insert to fail on a sign-in still signs the person in, and the next entry has `missedEntries: 1`. Test in Task 2.
3. 25 failed sign-ins for one address from one IP within 10 minutes give one entry with `attempts: 25`; a different IP gives a second entry. Test in Task 2.
4. An API key creation entry contains the key's id and name, never the key. Test in Task 2.
5. A member, a guest and an OAuth token without `admin` all get FORBIDDEN on `auditEntries`. Test in Task 1.

### Task 1: Audit core, API and retention

**Files:** `packages/db/src/schema/app.ts` + `0068_*` (`audit_entry`: id, type, actor_id → user set null, ip, country_code, metadata jsonb, request_information jsonb, created_at; indexes on created_at desc, (type, created_at), (actor_id, created_at); `organization.audit_retention text default '30d'`); `apps/api/src/audit/{store,types,context,retention}.ts`; `apps/api/src/graphql/resolvers/audit.ts`; instance endpoints `GET/POST /instance/audit-settings`; internal route `/internal/audit/cleanup` + worker job (daily); `apps/api/AGENTS.md`; tests `apps/api/src/audit/__tests__/integration/audit.test.ts`.

**Interfaces:**
- Produces:
  - `AUDIT_TYPES: Record<AuditType, string>` (every type in the spec with a one-line description); `type AuditType`.
  - `recordAudit(type: AuditType, metadata: Record<string, unknown> | null, opts?: { tx?: Tx; actorId?: string | null }): Promise<void>` — with `tx`, inserts in it and lets errors propagate; without, catches, logs `[audit] entry not written`, counts the miss.
  - `recordLoginFailed(address: string, reason: string)` (the 10-minute fold).
  - `withAuditRequest<T>(details: AuditRequestDetails, run: () => T): T`, `auditRequestFrom(request: Request, auth?: RequestAuth): AuditRequestDetails` (`{ ip, countryCode, userAgent, method: 'session' | 'apiKey' | 'oauth' | 'accessKey' | 'worker' | 'system', oauthApp?: { id, name }, pipelineId?, operation? }`), wired around GraphQL execution, the instance plugin handlers and internal routes.
  - GraphQL `auditEntries(filter: AuditEntryFilter, first, after, …)` and `auditEntryTypes`; `AuditEntry` fields.
  - `getAuditRetention()`, `setAuditRetention(user, value)` (owners; records `auditRetentionChanged`), `cleanupAuditEntries(now)`.
